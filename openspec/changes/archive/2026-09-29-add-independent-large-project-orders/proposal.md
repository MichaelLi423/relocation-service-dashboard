# Proposal

## Why

客户的工作范围新增中大型项目开单，但这类工作不属于现有小型搬迁项目；负责人只需记录开单工作量，不需要为其管理搬迁项目状态或进度。现有界面只能在项目上下文登记开单，无法让中大型工作独立登记并在月度报表中单独核对。

## What Changes

- 在工作台顶部“二维码申请”之后增加“中大型项目开单”独立入口；表单沿用开单类型、服务单号、开单日期和可后补的工程师，并增加必填客户单位。
- 中大型是与现有四类开单类型正交的工作范围分类，不新增第五种开单类型；四类中大型开单均不关联任何搬迁项目，不创建后台虚拟项目，也不参与项目状态和进度。
- 普通搬迁开单继续要求关联搬迁项目；仅中大型独立入口的搬迁开单允许无项目关联。所有开单共用服务单号全局唯一、开单日期归属、补录、删除和按单号计一次工作量的规则。
- 在跨项目历史中标识中大型开单；月度开单量计入现有总量，并新增工作范围筛选及明细/导出一致性。既有无项目开单不得仅凭无项目关联被追认为中大型；项目区域和标签筛选仍排除无项目记录，并向用户说明这一口径。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `service-order-recording`: 增加独立中大型工作范围及仅对其生效的无项目搬迁开单例外，保留既有开单约束。
- `operational-reporting`: 月度开单量增加工作范围筛选，保持总量、下钻、导出及无项目记录的项目维度筛选口径一致。
- `workbench-interface`: 增加独立顶部入口与表单，并在历史记录和报表界面提供分类辨识及筛选反馈。

## Impact

- 预计涉及工作台表单/历史/报表界面、共享 IPC 契约、主进程开单动作、开单领域服务、SQLite 追加迁移与读仓库，以及报表计算/导出和相应测试。
- 既有项目、进单、财务和项目生命周期不新增业务记录或状态；既有开单的工作范围在迁移后保持“非中大型/既有”语义，不自动追认。
