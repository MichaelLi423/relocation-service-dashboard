## Why

现有工作台允许部分登记事实直接编辑，但未将可编辑字段、不可变身份、需要新增更正或受保护删除重录的边界统一为可验收契约。这会让人工修正、历史导入 forward-fix 与缓存读取之间发生静默覆盖或历史漂移的风险。

## What Changes

- 新增“安全记录编辑”能力，定义各类记录的字段级编辑白名单、稳定 ID 重命名、唯一性、不可原位编辑、更正与终态规则。
- 仪器仅可编辑型号、UPS、二维码是否申请和所属批次；身份字段不可变，同批次保存不产生改批历史。
- 开单仅可编辑备注；标签组和标签仅可按稳定 ID 重命名，并保持各自名称唯一。
- Ship-to、序列号地址、到访/工作、验收、二维码申请与掉票遵守事实不可原位编辑；分别采用新增更正、受保护删除后重录或既有撤销终态。
- 人工修改不得刷新历史导入的目标快照或 hash；后续 forward-fix 必须冲突而非覆盖人工值。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `relocation-execution`: 限定仪器原位编辑字段、同批保存零写及跨批的原子失败语义。
- `service-order-recording`: 限定开单仅可维护备注，并保护人工备注不被导入 forward-fix 覆盖。
- `local-data-persistence`: 为标签组/标签稳定 ID 重命名和名称唯一性提供事务边界。
- `workbench-interface`: 提供受控编辑入口、不可编辑事实的更正提示及粗粒度有界读取模型刷新。

## Impact

- 影响 renderer 编辑入口、共享 IPC 契约、主进程领域服务与 SQLite 写事务。
- 不新增可编辑的 Ship-to 或历史事实版本模型；不改变项目取消、掉票撤销和生命周期唯一入口。
- 不改变历史导入的原子提交、目标快照和幂等语义，仅禁止人工编辑污染其 forward-fix 比对基线。
