## Context

系统为本机 SQLite 桌面应用；renderer 只能通过 preload 和共享 IPC 契约访问主进程。业务日期使用 `yyyy-mm-dd`，审计时间使用 ISO，状态转换与校验唯一入口为 `lifecycle.ts`。既有历史导入以来源键、目标快照和 hash 判断能否 forward-fix；既有 Ship-to、序列号地址、上门/工作、验收、二维码申请及掉票均为业务事实，而非可随意覆盖的表单草稿。

## Goals / Non-Goals

**Goals:**

- 将每类记录的允许编辑字段和更正路径固定在主进程写边界。
- 保留事实身份、历史和导入保护；避免一次保存出现部分写入、错误历史或陈旧缓存。
- 让可重命名的标签组/标签保持稳定 ID 与明确唯一性。

**Non-Goals:**

- 不为不可编辑事实增加“直接编辑”入口或隐式版本覆盖。
- 不修改 Ship-to 的不可变性、掉票撤销终态、项目取消语义或生命周期规则。
- 不让人工修改重算、替换或伪造历史导入的 target snapshot/hash。

## Decisions

### 1. 字段白名单由领域写边界执行

编辑请求必须带稳定记录 ID；主进程在单一写事务内读取当前记录、校验状态与字段白名单，并仅接受下列字段：

| 记录 | 允许原位编辑 | 禁止原位编辑 / 更正路径 |
| --- | --- | --- |
| 搬迁仪器 | `model`、UPS、二维码是否申请、所属批次 | 仪器名称、序列号、项目/合同归属及其他身份字段不可变；跨批次变更按既有改批规则保存历史 |
| 开单 | 备注 | 日期、服务单号、类型、工程师、客户单位及项目关联不可变；错误须删除后重录（受既有删除约束保护） |
| 标签组、标签 | 显示名称 | 稳定 ID、组/标签归属及项目标签关联不因重命名改变；结构变更走既有独立动作 |

当允许字段的提交值与当前持久化值全部相同时，保存为零写：不得生成改批历史、审计改批或无意义业务更新。批次不同则仍须遵守运输开始前可改批、运输开始后拒绝、并保存改批历史的既有规则。若仪器字段更新或改批任一校验失败，事务回滚全部写入；不得留下仅更新部分字段或仅写入改批历史的状态。

### 2. 事实不得原位编辑

Ship-to 主数据、序列号地址更新、到访活动与工作事实、验收、二维码申请和掉票不提供原位编辑命令。更正路径固定如下：

- Ship-to 地址变化：新建 Ship-to 申请，完成后产生新的不可变 Ship-to；原主数据与引用保持不变。
- 序列号地址、到访/工作、验收、二维码申请：仅可在无下游依赖且既有删除策略允许时，经确认后原子删除并重新登记；有依赖、影响状态或既有策略禁止删除时拒绝并说明原因。不得通过更新原行伪造历史。
- 掉票：不得删除或编辑已撤销记录；有效掉票保持既有可编辑范围，撤销后为终态。撤销后的金额或日期错误必须新增有效掉票更正，不得重新激活或覆盖撤销行。

### 3. 名称唯一性在事务中按稳定 ID 排除自身

标签组名称在全局归一化（去除首尾空白后）唯一；同一标签组内标签名称按同一归一化规则唯一。重命名只更新目标稳定 ID 的显示名称，检查排除自身；与其他 ID 冲突时拒绝，不自动合并、删除、重分配项目标签或改写历史关联。重命名命令和结果不得枚举或返回全部受影响项目 ID。

### 4. 人工写入与历史导入基线隔离

人工编辑成功时，业务记录正常更新其自身审计/修订，但不得更新、重建或替换任何历史导入来源审计中的 target snapshot、target hash 或来源摘要。下一次来源键相同的历史导入尝试 forward-fix 时，导入服务必须以保留的上次导入后快照/hash 比对当前目标；不一致即报告目标冲突并整体阻止该次导入写入，保留人工值。缺少可信基线同样冲突，不得猜测或覆盖。

### 5. 原子性与缓存失效

每次成功编辑、确认删除重录或重命名在同一 SQLite 写事务内完成字段/状态/唯一性校验、业务写入与必要审计。失败、冲突或越权字段不得留下部分写入。成功提交后仅进行 bounded 粗粒度缓存失效：标签库、项目列表与当前打开项目详情在下次读取时重新获取；不得枚举全部受影响项目 ID，也不得尝试逐项目精确失效。统计和历史浏览在其下一次有界读取时重新获取。导入快照/hash 不是可刷新的缓存项，读取结果不得以旧值覆盖提交结果。

## Risks / Trade-offs

- 删除重录会保留较少的原始行历史，但比覆盖事实安全；删除受现有依赖和生命周期保护。
- 严格导入冲突会要求负责人处理来源与人工修改差异，但可防止静默丢失人工修正。
- 标签重命名不合并同名实体，避免稳定 ID 与既有项目关联漂移。

## Verification

以 focused domain/integration 测试验证字段拒绝、全量无变化保存零写、跨批事务回滚、标签唯一性冲突零变化、不可编辑事实的更正路径、粗粒度缓存失效以及开单人工备注的导入冲突；以 typecheck 验证 IPC 契约。无需全量测试，除非 focused 验证揭示更广回归。
