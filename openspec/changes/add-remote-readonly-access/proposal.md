## Why

搬迁负责人需要让一名远程手机使用者在不接触桌面 SQLite 原始库、也不改变桌面离线工作方式的前提下，查看最新的汇总和业务明细。当前基线禁止云同步与应用内登录，因而需要明确、受限地为显式启用的远程只读访问划出边界。

## What Changes

- 增加桌面端显式启用的只读发布：从一致的本机 SQLite 备份生成字段白名单、独立版本化的移动端投影；默认不外发，停用时停止新上传，并明确远程副本保留/删除处理。
- 增加仅经私有 WireGuard 与受信 HTTPS 访问的远程只读服务；一个独立的远程身份使用密码、TOTP 和离线恢复码，且不改变桌面无密码本地身份。
- 增加手机浏览器只读工作台，展示汇总、业务明细、最后一次已确认的有效快照及源端确认的新鲜度；健康条件下交付目标为 5 分钟、超过 10 分钟未确认时警告。
- 保持本机 SQLite 为唯一业务事实源和唯一写入方；不提供远程业务变更、导入导出、清理、恢复、双向同步、本地 API 暴露或离线业务缓存。未来远程写入须另行提案并以云端为唯一权威，禁止双主。
- 将域名/信任链、真实安全组与网络隔离、资源容量和生产隔离决策作为部署闸门；不因未具备域名而降低认证或网络边界。现有 ECS 仅为待核验的试点候选，不承诺容量或可用性。

## Capabilities

### New Capabilities

- `remote-readonly-publication`: 负责人显式发布并有序、幂等地激活不可变的只读移动端投影，防止旧版本回退，并在源代际变化时全量替换。
- `remote-readonly-access`: 在私有网络和受信 HTTPS 边界内，为独立远程身份提供受限的只读快照访问与认证恢复。
- `mobile-readonly-workbench`: 为手机浏览器提供无离线业务缓存的汇总和业务明细只读视图，以及最后有效快照和新鲜度状态。

### Modified Capabilities

- `local-data-persistence`: 将“不向远程发送业务数据”的绝对禁止调整为默认不外发、仅可由负责人显式启用的字段白名单只读投影发布，同时保持本机 SQLite 为唯一业务事实源和唯一写入方。
- `workbench-access`: 在保留桌面本地直接进入、无密码、无多账号/角色及本地用户不构成访问门槛的要求下，允许独立的单一远程只读身份使用密码、TOTP 与离线恢复码访问远程投影。
- `workbench-interface`: 将启动直达与既有任务指挥台结构明确限定于桌面工作台，补充不干扰核心操作的发布控制与状态入口；手机入口遵循独立的只读信息架构。

## Impact

影响桌面发布控制和只读 DTO/仓储边界、远程投影接收与只读 API、手机 React 页面、WireGuard/HTTPS 与 Alibaba ECS 部署配置。不得直接暴露原始 SQLite 备份或既有 Workbench API；远程数据不成为业务权威或写入路径。
